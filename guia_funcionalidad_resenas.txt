GUÍA COMPLETA: RESEÑAS + INCIDENCIAS (POO) CON MAPA DE LÍNEAS Y CONTEXTO
=========================================================================

Objetivo general
----------------
Esta guía documenta la implementación actual de:
1) Reseñas por pedido (con borrador, cancelar y finalizar).
2) Incidencias por pedido (con borrador, cancelar y finalizar en el mismo flujo).
3) Visualización de reseñas en producto y listado de incidencias para gerente.
4) Refactorización a Programación Orientada a Objetos (entidades + DAOs hidratando objetos).

La guía está escrita con:
- archivos creados,
- archivos modificados,
- código y fragmentos,
- contexto exacto de inserción,
- líneas actuales de referencia.

    public function getValoracion(): int { return $this->valoracion; }

2.1) includes/MySQL/02-tablas.sql
----------------------------------
Modificación 1: tabla `resenas`
- Contexto: tras tablas funcionales previas, antes del cierre de FK checks.
- Líneas actuales: 153-166

Bloque:
CREATE TABLE IF NOT EXISTS `resenas` (
    `id` INT AUTO_INCREMENT PRIMARY KEY,
    `usuario_id` INT NOT NULL,
    `producto_id` INT NOT NULL,
    `pedido_id` INT NOT NULL,
    `texto` TEXT,
    `valoracion` TINYINT NOT NULL,
    `fecha_creacion` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (`usuario_id`) REFERENCES `usuarios`(`id`) ON DELETE CASCADE,
    FOREIGN KEY (`producto_id`) REFERENCES `productos`(`id`) ON DELETE CASCADE,
    FOREIGN KEY (`pedido_id`) REFERENCES `pedidos`(`id`) ON DELETE CASCADE,
    CONSTRAINT `chk_resenas_valoracion` CHECK (`valoracion` BETWEEN 1 AND 5),
    UNIQUE (`usuario_id`, `producto_id`, `pedido_id`)
);

Modificación 2: tabla `incidencias`
- Contexto: inmediatamente después de `resenas`.
- Líneas actuales: 168-173

CREATE TABLE IF NOT EXISTS `incidencias` (
    `id` INT AUTO_INCREMENT PRIMARY KEY,
    `pedido_id` INT NOT NULL,
    `incidencia` VARCHAR(1000) NOT NULL,
    FOREIGN KEY (`pedido_id`) REFERENCES `pedidos`(`id`) ON DELETE CASCADE

=====================================
3) FLUJO FINAL (RESEÑAS + INCIDENCIAS)
=====================================

3.1) Flujo reseñas
- Entrada: histórico/listado de pedidos.
- Condición: pedido entregado y no reseñado.
- En proceso:
  - guardar reseñas por producto en borrador de sesión,
  - cancelar: borra borrador,
  - finalizar: inserta reseñas y bloquea repetición por `UNIQUE` + validación.

3.2) Flujo incidencias
- Entrada: misma pantalla `vistas/resenas/proceso.php`.
- Incidencia opcional del pedido:
  - guardar borrador,
  - cancelar proceso: borra borrador incidencia,
  - finalizar: persiste incidencia si hay texto.

3.3) Flujo gerente
- Panel gerente -> botón “Ver incidencias” -> tabla historial con pedido asociado.


====================================================
4) PARTE DE INCIDENCIAS AL MISMO NIVEL QUE RESEÑAS
====================================================

Resumen técnico equivalente (simetría funcional):
- Persistencia:
  - Reseñas: tabla `resenas`.
  - Incidencias: tabla `incidencias`.
- Capa DAO:
  - Reseñas: `ResenaDAO`.
  - Incidencias: `IncidenciaDAO`.
- Capa Service (borrador sesión):
  - Reseñas: `ResenaService`.
  - Incidencias: `IncidenciaService`.
- Vista de proceso:
  - Reseñas por producto + incidencia opcional integradas en `vistas/resenas/proceso.php`.
- Visualización:
  - Reseñas por producto: `vistas/resenas/ver.php`.
  - Incidencias global gerente: `vistas/preparacion_pedidos/incidencias.php`.
- POO en presentación:
  - Reseñas e incidencias se renderizan con getters de entidad.
